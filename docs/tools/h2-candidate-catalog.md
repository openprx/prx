# H2 candidate catalog

`prx skills lifecycle experiment product catalog [--after-skill <id>]` reads a bounded page from the existing target owner's store. The service API is `catalog_product(&ExperimentCatalogRequest, &Config) -> Result<ExperimentCatalog, ExperimentProductError>`. `after_skill` is an advisory lexicographic skill cursor, not a stable snapshot or a grant. Controlled native adapters must verify their fresh source-owned invocation and target store before calling the same service; catalog reads do not execute or revive an experiment root.

Only skill IDs, short display names/descriptions and candidate pattern IDs/short statements are returned. Pattern contents are checked against the original content identity and the derived index. Revision metadata must match the active binding's pinned record digest. Bundles, suite cases, grading oracles, raw experience bodies, approval material and owner MACs are excluded. This projection does not prove current proposal eligibility: Plan still performs the original full owner validation.

A page contains at most 16 skills and 8 candidate patterns per skill. Names are limited to 128 UTF-8 bytes, descriptions/statements to 256. Encoded output is below 32 KiB, including JSON escaping; 2 KiB is reserved for cursor/counters/observations. Input is capped at 2 MiB total and 256 KiB per record. The active directory admits 512 enumerated entries including invalid names; a single overflow probe produces an unavailable page rather than a false empty result. At most 1,024 index entries are examined. Every actual file read is charged and bounded, uses the existing private-path rules and refuses final symlinks. The existing shared owner lock and a cooperative 500 ms scan deadline apply. This deadline is not a hard cancellation guarantee for operating-system filesystem calls.

`state` is `complete`, `partial` or `unavailable`. File failures, unsafe records, exhausted budgets and truncation appear in bounded observations. `unavailable` with an empty list does not mean that no skills or patterns exist. A missing/unreadable pattern index makes pattern discovery partial even when skill metadata is readable. Pattern windows are bounded candidate suggestions, not exhaustive pattern pagination. `next_after_skill` advances a truncated skill page; re-reading can observe later owner changes.

This is candidate business code pending concentrated type, regression and actual native-entry validation. No new authority, accounting owner, grant registry or publication path is introduced.
